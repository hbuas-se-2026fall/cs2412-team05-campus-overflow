# ADR-011：覆盖率门禁采用领域层口径

**状态**：已接受 ｜ **驱动特征**：可维护性、可验证性、投入产出比

## 背景

Lab 7 要求「单元测试覆盖率 70% 以上，核心聚合 90%+」。团队接入了两套工具：

- **JaCoCo**：按模块统计行覆盖，`domain.coverage.minimum` 绑定在 Maven 构建中，是**构建期硬门禁**；
- **SonarQube**：在 CI 中临时起实例扫描，覆盖率数据同样来自 JaCoCo 报告，但**分母是整个 `backend/`**。

两套工具给了两个数字，差距很大：

| 口径 | 覆盖率 | 分母包含 |
| --- | --- | --- |
| JaCoCo 领域层 | **100%**（65/65、177/177、95/95、182/182、211/213） | 仅五个 `domain` 模块 + 共享内核 |
| SonarQube 全层 | **40.0%**（8361 行） | 全层：含 `infrastructure`、`interfaces`、`bootstrap` 装配代码 |

`sonar-project.properties` 里写着「覆盖率 > 70%」，于是出现了一个必须回答的问题：
**这条 70% 是对谁要求的？** 不回答清楚，团队会反复争论「40% 算不算达标」，而这个争论本身没有任何产出。

## 决策

**覆盖率门禁以 JaCoCo 的领域层口径为准，SonarQube 的全层覆盖率作为观测指标，不作为门禁判据。**

具体：

1. 构建期硬门禁：`domain.coverage.minimum = 0.70`，核心聚合 `co-qa-domain` 单独 `0.90`（实际已达 1.00）。
2. `sonar-project.properties` 的阈值声明改为**口径说明**，明确「70% 指领域层」，不再留下会被误读成全层要求的表述。
3. `Bugs = 0`、`Vulnerabilities = 0` 两项仍按**全层**口径执行（当前均为 0，可靠性评级 A）。
4. 全层覆盖率作为趋势指标记录在 `docs/verification/`，用于观察 `infrastructure` / `interfaces` 的测试欠账，但**不卡合并**。

## 理由

- **风险集中在领域层**。计分规则、采纳状态机、余额守卫、相关度排序——这些算错会直接产生业务后果。`infrastructure` 里大量是 Spring 装配与 JPA 适配器，它们的正确性更多依赖集成测试与端到端验证，而不是单元测试的行覆盖。
- **分母不同，数字不可比**。把 100%（领域层）和 40%（全层）并列讨论「达标与否」，等于拿两个不同的量表量同一件事。
- **投入产出比**。把全层从 40% 补到 70%，意味着给 12 个尚未测的模块（含 `interfaces`、`bootstrap`）写大量样板断言，收益主要是让一个数字好看，而不是减少真实缺陷。

## 后果

**正面**

- 门禁含义清晰：`mvn verify` 失败 = 领域层覆盖不足，责任人明确。
- 不再有「40% 算不算达标」的反复争论。
- 全层数字保留为趋势指标，欠账可见但不阻塞交付。

**负面 / 已知欠账**

- 全层 40% 意味着 `identity` / `reputation` 的 `application` 层与各 `infrastructure` 模块确实缺测试，这是真实欠账，写在这里而不是藏起来。
- 后续若要提升，建议按风险排序：`ReputationEventHandlers`（跨上下文事件消费，最易静默出错）→ `BountyService` 边界 → 各适配器。

## 被否决的替代方案

- **补齐全层 70%**：需要覆盖 12 个模块约 5000 行，主要是装配与适配器样板；时间成本以周计，且对领域正确性没有增量保护。否决。
- **放弃 SonarQube、只留 JaCoCo**：会丢掉 Bugs / Vulnerabilities / Code Smell 这些 JaCoCo 不提供的信息——事实上 2 个 Bug 正是 Sonar 报出来的。否决。
- **把 `sonar-project.properties` 的 70% 改成 40%**：那是把门禁降到现状，等于取消门禁。否决。

## 证据

- 领域层实测：`docs/team/coverage-baseline.md`
- 全层扫描与复扫：`docs/verification/sonarqube-2026-11-11.md`（首次 Bugs 2 → 修复后 0，可靠性 C → A）
- 门禁配置：`backend/pom.xml`（`domain.coverage.minimum`）、`backend/sonar-project.properties`
