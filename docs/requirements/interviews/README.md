# 用户访谈：提纲与记录模板（Lab 2 前置作业）

> **当前状态：本目录尚无任何访谈记录。**
> 指导书 Lab 2 的【环境与前置准备】要求「每队至少 3 份真实访谈记录」，这一项目前是 0 份。
>
> 本文件**只是提纲和空白模板**，不包含任何访谈内容。
> 访谈必须真实发生——编造访谈记录违反指导书 §9.3 学术诚信红线，比缺一份材料严重得多。

## 怎么用

1. 找 3 位同学（或 1 位教师 + 2 位同学）各聊 **10–15 分钟**，线上语音或面对面都行
2. 照着下面的提纲问，但**不要照着念**，把他说的原话记下来
3. 每人复制一份模板为 `user-interview-YYYY-MM-DD-<代号>.md` 填进去
4. 提交 PR 合进本目录

受访者姓名可以只写代号（如 `S1` / `T1`），但访谈本身必须真实。

---

## 访谈提纲

### A. 现状与痛点（先问事实，不要先问功能）

1. 最近一次你遇到课程上的问题（作业环境、概念不懂、报错查不出来），是怎么解决的？花了多久？
2. 那个过程中你问过谁？在哪个群/哪个平台问的？对方多久回复？
3. 你在群里问问题时，最让你不想再问的是什么？（没人理 / 答非所问 / 同一个问题被重复问很多遍 / 不敢问显得笨）
4. 你有没有用过 Stack Overflow、CSDN、掘金这类平台？为什么用或者为什么不用？

### B. 对「课程问答社区」的预期

5. 如果有一个只对本校课程开放的问答区，按课程分区、能看到教师认证的答案，你会用吗？什么情况下会用？
6. 你希望它有什么是群聊做不到的？（历史可搜索 / 答案被沉淀 / 老师能看到 / 有人帮你验答案对不对）
7. 看到一条对你有用的回答，你通常会怎么表示？（点赞 / 采纳 / 发个红包 / 什么都不做）

### C. 参与动机与顾虑

8. 什么情况下你愿意花时间去回答别人的问题？（被采纳有成就感 / 涨积分排名 / 帮朋友 / 老师的课加分）
9. 如果你回答了但没人理，你还会继续答吗？
10. 你会担心什么？（被同学看到自己问「很简单」的问题 / 隐私 / 刷屏水贴 / 被拿去举报作业抄袭）

### D. 收尾

11. 如果这个系统明天就能用，你第一件想拿它做的事是什么？

## 记录模板

> 复制以下内容，另存为 `user-interview-YYYY-MM-DD-<代号>.md`

```markdown
# 用户访谈记录 · <代号>

| 项 | 内容 |
| --- | --- |
| 日期与时间 | YYYY-MM-DD HH:MM（约 N 分钟） |
| 受访者代号 | S1 |
| 身份 | 大二学生 / 助教 / 授课教师 |
| 使用过的问答平台 | 课程群、CSDN、Stack Overflow… |
| 访谈人 | <姓名> |
| 记录方式 | 现场记录 / 录音转写 |

## 关键原话（至少 3 句，尽量保留原话）

1. 「……」
2. 「……」
3. 「……」

## 访谈纪要

### 现状与痛点

（他目前怎么解决问题、花了多久、卡在哪）

### 对功能的具体期待

（他明确说想要 / 明确说不想要的，分开写）

### 顾虑

（隐私、刷屏、被看见等）

## 对 Backlog 的影响

| 结论 | 对应 US |
| --- | --- |
| 被验证（真实痛点） | US-0xx |
| 被否决（我们认为重要，他认为不重要） | US-0xx |
| 新发现（原 Backlog 没有） | — |

> 这一栏是访谈真正的价值：证明 Backlog 不是拍脑袋排的。
```

## 三份访谈的覆盖建议

为了让材料更有说服力，建议三个受访者**角色不同**：

| 代号 | 角色 | 为什么选 |
| --- | --- | --- |
| S1 | 低年级学生 | 提问方视角：最怕问出「笨问题」 |
| S2 | 高年级学生 | 回答方视角：什么值得他花时间答 |
| T1 | 教师或助教 | 权威方视角：为什么需要「教师认证答案」、为什么关心问题是否被解决 |

三个都问学生也行，但角色重复会让「访谈验证了 Backlog」这句话变弱。
