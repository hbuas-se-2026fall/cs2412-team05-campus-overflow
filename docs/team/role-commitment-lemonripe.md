## 一、我承诺做到的

**作为 Developer · 后端**

1. **按章程 §3 执行**：feature 分支开发、小步提交、PR ≤ 400 行、不向 `main` / `develop` 直推；分支命名与提交信息遵循约定式提交。
2. **Reputation / Discovery 上下文的后端实现**：与组长对齐接口契约后动工，先写领域测试再补实现，不越过领域层在控制器里堆业务。
3. **我改的代码我负责**：自测通过再提 PR，PR 描述写清变更范围、验证方式与关联 Issue；不把「测试留给 QA」当默认。
4. **评审响应及时**：被 @ 到的评审意见 24 小时内响应；阻塞级意见（/blocking）必须解决并复评后才请求二次合并。
5. **补位意识**：前端联调阶段主动承担接口联调与 Mock 数据维护，与组员C 协作不甩锅。

## 二、我接受被这样考核

- 我提交的 PR 因自测不充分被打回 → 记为失职，在站会说明。
- 我负责的模块出现越层调用（控制器直查仓储等架构约束违反）→ 按评审清单整改，并在回顾会复盘。
- 承诺的任务延期且未提前暴露 → 视为阻塞点管理失败，由 SM 记录。
